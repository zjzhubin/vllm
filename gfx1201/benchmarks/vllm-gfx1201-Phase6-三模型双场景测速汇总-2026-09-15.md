### 2.3 等效启动命令（逐字）

**场景 A（原始）**：

```bash
docker run -d --name w07hb-fp8a \
  --device=/dev/kfd --device=/dev/dri --group-add video --group-add 991 \
  --ipc=host --shm-size=16g --network host --security-opt seccomp=unconfined \
  -v /opt/models:/models \
  -v /opt/cache/triton:/root/.triton \
  -v /opt/cache/vllm:/root/.cache/vllm \
  -v /opt/cache/aiter:/root/.aiter \
  -e VLLM_CACHE_SUBDIR=w07hb-fp8a \
  -e HIP_VISIBLE_DEVICES=0,1 \
  -e VLLM_ROCM_USE_AITER=1 -e VLLM_ROCM_USE_AITER_UNIFIED_ATTENTION=1 \
  -e VLLM_ROCM_USE_AITER_TRITON_ROPE=1 -e VLLM_ROCM_USE_AITER_LINEAR=1 \
  -e VLLM_ROCM_USE_AITER_LINEAR_HIPBMM=1 -e VLLM_ROCM_USE_AITER_TRITON_GEMM=1 \
  -e VLLM_ROCM_USE_AITER_RMSNORM=1 -e VLLM_ROCM_USE_AITER_MHA=1 \
  -e VLLM_ROCM_USE_AITER_CUSTOM_AR=1 -e VLLM_ROCM_USE_AITER_FP4_ASM_GEMM=0 \
  -e AITER_ROPE_NATIVE_BACKEND=1 -e FLASH_ATTENTION_TRITON_AMD_ENABLE=TRUE \
  -e RDNA_AITER_SAMPLER=1 -e KV_GROUP_SIZE=8 \
  phase6:07-s2ar-latest \
  /opt/venv/bin/vllm serve /models/Qwen_Qwen3.8-27B-FP8 \
  --served-model-name fp8 --port 8012 --tensor-parallel-size 2 \
  --max-model-len 262144 --max-num-seqs 16 --enable-chunked-prefill \
  --max-num-batched-tokens 4096 --gpu-memory-utilization 0.8 \
  --kv-cache-dtype fp8 --enable-prefix-caching \
  --attention-backend ROCM_AITER_UNIFIED_ATTN
```

**场景 B（+DFlash2-FP8 草稿 ns=3；mml=98304）**——同上骨架改：`--name w07hb-fp8d`、`-e VLLM_CACHE_SUBDIR=w07hb-fp8d`、`--served-model-name fp8d`、`--max-model-len 98304`，末尾加：

```bash
  --speculative-config '{"method":"dflash","model":"/models/tcclaviger_Qwen3.8-27B-DFlash2-FP8","num_speculative_tokens":3,"attention_backend":"ROCM_AITER_UNIFIED_ATTN"}'
```

> 场景 B mml=98304 的原因：GMU0.8+草稿下 FP8 权重（27B×1B/卡）挤压 KV 池，mml262144 起服记账失败（可用池 2.4-3.26 GiB 浮动 <需求 4.47 GiB）；96k=经验证可复现口径（v2 复测 READY_OK 163s）。mml 不改 kernel/池，仅改允许最大请求长，数字与 262144 族可比（176128 版对照 Δ≤2.7%）。

## 七、系统发现与生产建议

### 7.1 FP8+dflash 128k refill 静默挂起（⚠ 生产风险）

- 形态：ReadTimeout×2；引擎步进日志静默、kv_cache_usage_perc 反降 0.78→0、token 计数冻结、零错误行
- 对照：FP8 无草稿 128k 正常（2324 tok/s）；cyankiwi+W4A16 草稿 128k 正常（1581）→ **FP8 目标模型+FP8 草稿+长上下文组合特有**
- 生产风险面：生产 qwen36 同组合（GMU0.92/mml262144）长上下文（>96k 请求）存在同风险——建议生产侧长上下文请求路由至无草稿或 INT4 路径，或对 FP8+dflash 限 mml；根治需专项排查（挂账）

### 7.2 KV 池可用量=多因子（非单因子）

- 同 FP8 目标 mml262144：带 FP8 草稿 3.26 GiB vs 无草稿 6.26/6.92 GiB（草稿权重占池）
- INT4+dflash：7.99 GiB（被验）/5.81 GiB（复测，−27%）
- 同配置 boots 间浮动 −26%~−28.5% 且下界无收敛迹象（AOT/cudagraph 记账浮动族）
- 结论：**GMU0.8+mml262144+FP8+草稿=起服记账失败**（需求 4.47>可用 2.4-3.26）；mml 设计须按最坏池+草稿开销；生产 GMU0.92 依赖更大预算+无草稿场景余量充足
- 修正记录：批2「权重精度单因子」表述经 bv 盲区证伪，本报告按多因子口径（台账 P6-351）

### 7.3 窗口态（判例 1/3 沿用）

- dflash 场景 c1 双遍跨度 38%（FP8 49.2↔68.3；cyankiwi 53.1↔73.3）=本批新纪录族
